# Copilot in practice

::: lede
Getting real work done with Microsoft Copilot in Outlook, Word, Excel, Edge and Chat. Built for a non-technical team, using the team's own proposals, tenders, marketing and client work. The point is not to memorise the product. The point is to know what Copilot can see, carry context between apps on purpose, and check the result before it goes out.
:::

## The one idea

You are the orchestrator.

Copilot keeps Curtin's data inside the tenant, but it does not pass work between apps for you. Copilot in Outlook can see the email you have open. Copilot Chat in the browser cannot, unless you paste the text or upload the file. Copilot in Word knows the document, not the thread that led to it.

So the skill is not "automate the chain". The skill is to get the right context in front of the right Copilot, then carry the output to the next step yourself.

```{=html}
<div class="flow">
  <div class="step"><b>1 Gather</b><span>Open the email, document or page that holds the context.</span></div>
  <div class="step"><b>2 Extract</b><span>Ask for the decisions, dates, asks and numbers. Keep it short.</span></div>
  <div class="step"><b>3 Carry</b><span>Copy it into the next app and say where it came from.</span></div>
  <div class="step"><b>4 Refine</b><span>Ask for the shape you need in the destination.</span></div>
  <div class="step"><b>5 Check</b><span>Names, figures, commitments. Before it moves on.</span></div>
</div>
```

## The morning

Five short blocks. Two teaching, two hands-on, one commit at the end.

:::::: {.cards .five}
::: {.card .s1}
[01 · 9:00]{.lab}

### Open

The problem, the one idea, and a five-minute context pre-flight. Everyone checks what their own Copilot can see.
:::

::: {.card .s2}
[02 · 9:15]{.lab}

### Judge

Where Copilot helps, where it trips you up, and the rules on what may go in. A live demo of why it agrees with you when you push back.
:::

::: {.card .s3}
[03 · 10:00]{.lab}

### See

The three things that decide what Copilot knows: the app, the licence, the tenant. Then the carry pattern, end to end.
:::

::: {.card .s4}
[04 · 11:00]{.lab}

### Build

Hands-on with a sanitised brief: outcomes, proposal outline, a red-team critique, and a budget table.
:::

::: {.card .s5}
[05 · 11:45]{.lab}

### Yours

Map one recurring workflow, build a reusable prompt, and put the human checkpoints in. Leave with two or three tasks.
:::
